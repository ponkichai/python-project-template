# 開発フロー（DDD → SDD → TDD → AIDD）— 正本

> 新機能はこのフローに従って作る。人間・AIエージェント共通。
> Claude Code では `/new-feature` スキルがこのファイルを参照して進行する。

| 順 | 略語 | 意味 | 成果物 |
|----|------|------|--------|
| 0 | **DDD** | Domain-Driven Design（ドメイン駆動設計） | `CONTEXT.md` の用語追記（必要時） |
| 1 | **SDD** | Spec-Driven Development（仕様駆動開発） | `specs/<機能名>.md` |
| 2 | **TDD** | Test-Driven Development（テスト駆動開発） | `tests/test_<機能名>.py`（失敗する状態） |
| 3 | **AIDD** | AI-Driven Development（AI駆動開発） | `src/<機能名>.py` |

## Step 0: ドメインを確認する（DDD）

ルート `CONTEXT.md` のユビキタス言語表を確認する。

- **既存の概念** → 表にある言葉をそのままSpec・コードで使う
- **新しい概念** → 先に `CONTEXT.md` の用語集に追記してから次に進む（用語・意味を1〜2文で）

ここで言葉を揃えておくことで、Spec・テスト・実装・会話の間で表現がぶれなくなる。
設計原則（命名一致・I/O分離・貧血モデル回避）は `docs/conventions.md` を参照。

## Step 1: Spec を作成する（SDD）

以下を明確にする（エージェントはユーザーに質問する）：

1. **機能名**（ファイル名に使うので英語スネークケース推奨）
2. **入力**：何を受け取るか（引数・型）
3. **出力**：何を返すか（戻り値・型）
4. **仕様**：処理のルール・条件
5. **除外スコープ**：やらないこと

回答を元に `specs/<機能名>.md` を `specs/_template.md` に従って作成する。

## Step 2: テストを生成する（TDD）

`specs/<機能名>.md` を読み、`tests/test_<機能名>.py` を生成する。

- 正常系：期待通りに動くケース（複数）
- 異常系：エラーが正しく出るケース
- 境界値：端のケース（0、空文字、None等）

この時点では実装が存在しないため、テストは全て失敗する。それでよい。

## Step 3: 実装を生成する（AIDD）

`specs/<機能名>.md` と `tests/test_<機能名>.py` を参照し、`src/<機能名>.py` の実装を生成する。

条件：

- 型ヒントを必ずつける
- `config/` から設定値を読む（ハードコードしない）
- Ruff lint が通るコードで書く

## Step 4: 検証

```bash
make check
```

を実行して lint・型チェック・全テストが通ることを確認する。
失敗した場合はエラーを分析して Step 3 に戻る。
