# new-feature スキル

新機能を SDD → TDD → AIDD の順で実装する。

## トリガー

「新機能」「new feature」「〜を実装したい」「〜を追加したい」と言われたら起動する。

## 手順

### Step 1: Spec を作成する（SDD）

ユーザーに以下を質問する：

1. **機能名**（ファイル名に使うので英語スネークケース推奨）
2. **入力**：何を受け取るか（引数・型）
3. **出力**：何を返すか（戻り値・型）
4. **仕様**：処理のルール・条件
5. **除外スコープ**：やらないこと

回答を元に `specs/<機能名>.md` を `specs/_template.md` に従って作成する。

### Step 2: テストを生成する（TDD）

`specs/<機能名>.md` を読み、`tests/test_<機能名>.py` を生成する。

- 正常系：期待通りに動くケース（複数）
- 異常系：エラーが正しく出るケース
- 境界値：端のケース（0、空文字、None等）

この時点では実装が存在しないため、テストは全て失敗する。それでよい。

### Step 3: 実装を生成する（AIDD）

`specs/<機能名>.md` と `tests/test_<機能名>.py` を参照し、
`src/<機能名>.py` の実装を生成する。

条件：
- 型ヒントを必ずつける
- `config/` から設定値を読む（ハードコードしない）
- Ruff lint が通るコードで書く

### Step 4: 検証

```bash
make test
```

を実行して全テストが通ることを確認する。
失敗した場合はエラーを分析して Step 3 に戻る。
